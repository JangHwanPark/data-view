# data-view

게임 기획 테이블처럼 여러 엑셀과 데이터베이스가 서로 얽혀 있는 데이터를, 기획서와 함께 한 화면에서 따라가며 확인하는 로컬 도구입니다.

테스트하면서 값 하나를 확인하려면 주문 파일에서 ID를 보고, 다른 파일을 열어 그 ID를 찾고, 또 다른 파일로 넘어가는 식으로 엑셀을 체이닝해야 합니다. data-view는 테이블 사이의 연결을 자동으로 찾아 값을 눌러 따라가게 하고, 기획서에 적힌 테이블 이름이나 ID가 실제 데이터의 어디인지 추론해서 이어 줍니다. 기획서와 데이터는 PC 밖으로 나가지 않습니다.

설계와 단계 계획은 [docs/DESIGN.md](docs/DESIGN.md)에 있습니다.

## 주요 기능

- 데이터 불러오기: 엑셀(xlsx, xls), CSV 파일, 폴더 경로 지정, MySQL/MariaDB 연결(직접 입력 또는 환경변수, .env 파일에서 읽기)
- 도메인 지도: 테이블을 업무 단위(파일, 이름 접두어)로 묶고 도메인 사이 연결을 그림으로 보여줌. 테이블마다 역할(시작점, 기준, 하위, 공통, 독립)을 붙이고, 테이블별 연결 화면에서 모든 테이블이 무엇을 가리키고 무엇에 가리켜지는지 한눈에 봄. 도메인은 직접 바꿀 수 있음
- 테이블 화면: 표 안 검색, 이어진 테이블 그림(1~2단계), 그 테이블을 설명하는 기획서 문장
- 테이블 사이 연결: 열 이름과 값으로 자동으로 찾고, 필요하면 관계로 저장. 관계 화면에서 직접 잇기, 추천, 다이어그램, 내보내기/가져오기
- 값 따라가기: 표에서 연결된 값을 누르면 이어진 테이블의 행이 오른쪽에 패널로 열리고 계속 이어서 따라감
- 값 검색, 합친 표(관계를 따라 여러 테이블을 하나로 합치고 엑셀로 내보내기, 연결 누락 행 표시)
- 기획서 연동: 워드, PPT, PDF, 엑셀 기획서를 읽어 테이블, 열, ID 이름을 실제 데이터와 규칙 기반으로 매칭. 기획서에만 있는 이름(옛 이름, 아직 없는 테이블)과 기획서에 없는 테이블을 따로 보여줌. 기획서의 ID를 누르면 그 행과 따라가기 패널이 열리고, 테이블 화면에서는 그 행이나 테이블 ID가 나오는 기획서 절로 이동
- 사이드바, 다크 모드

## 필요한 것

- Windows 10/11 (다른 OS도 동작하지만 실행 배치 파일은 Windows용입니다)
- [Node.js](https://nodejs.org) 20 이상 (개발은 24에서 했습니다)
- 테스트용 MySQL을 띄우려면 Docker Desktop (선택)

## 실행하기

IDE 없이 저장소 폴더의 `start.bat`을 더블 클릭하면 됩니다.

1. 처음 실행하면 패키지를 설치하고(`npm install`) 프로덕션 빌드를 만듭니다. 몇 분 걸릴 수 있습니다.
2. 서버가 `http://127.0.0.1:3000`에서 열리고 브라우저가 자동으로 열립니다.
3. 끝내려면 검은 창을 닫거나 `Ctrl+C`를 누릅니다.

코드를 새로 받았을 때(`git pull` 뒤)는 빌드를 다시 해야 바뀐 내용이 반영됩니다. 이때는 명령 창에서 아래처럼 실행합니다.

```bash
start.bat rebuild
```

직접 실행하려면 아래 순서입니다.

```bash
npm install
npm run build
npm run start
```

개발할 때는 `npm run dev`를 씁니다. 서버는 다른 PC에서 접속하지 못하도록 `127.0.0.1`에만 열립니다.

## 데이터 저장 위치

- 연 파일, 기획서, 관계, 용어 매칭: 브라우저 저장소(OPFS). 브라우저마다 따로 저장되고, 관계는 관계 화면에서 JSON으로 내보내 동료와 나눌 수 있습니다.
- 데이터베이스 접속 정보: 저장소 폴더의 `data/connections.json`. 비밀번호는 AES-256-GCM으로 암호화하고, 키는 `.env.local`의 `APP_SECRET` 또는 처음 저장할 때 만드는 `data/secret.key`를 씁니다. `data/`는 git에 올라가지 않습니다.

## 테스트 데이터

게임 테이블을 흉내 낸 테스트 데이터를 만들 수 있습니다. 15개 파일, 51개 시트, 약 5만 9천 행이고, 네 가지 참조 방식(단일 ID, 번호 붙은 여러 열, 한 칸 여러 ID, 타입+ID)과 일부러 넣은 깨진 참조, 중복 키가 들어 있습니다. 데이터와 일부러 어긋나게 만든 옛 기획서 4종(워드, PPT, 엑셀, PDF)과 정답 목록도 함께 만듭니다. PDF 기획서는 Windows의 맑은 고딕 글꼴로 만듭니다.

```bash
npm run fixtures
```

결과는 `fixtures/` 폴더에 생기고 git에는 올라가지 않습니다.

| 폴더 | 내용 |
| --- | --- |
| `fixtures/game` | 현재 버전 게임 데이터(엑셀 14개, CSV 1개) |
| `fixtures/game-prev` | 갱신본 비교용 이전 버전(Item, Quest) |
| `fixtures/docs` | 옛 기획서 4종과 `expected.json`(의도한 어긋남 목록) |
| `fixtures/mysql/seed.sql` | 같은 데이터를 MySQL에 넣는 SQL |
| `fixtures/env/test.env` | 환경변수 연결 시험용 .env |

테스트용 MySQL은 Docker로 띄웁니다. `npm run fixtures`를 먼저 실행해야 시드가 들어갑니다.

```bash
docker compose up -d
```

접속 정보는 `127.0.0.1:3307`, 데이터베이스 `game`, 읽기 전용 계정 `viewer` / `viewer`입니다(로컬 테스트용 값). 앱의 "소스 추가 > 데이터베이스 연결"에서 직접 입력하거나, `.env 파일 경로`에 `fixtures/env/test.env`의 전체 경로를 넣어 불러올 수 있습니다.

## 폴더 구조

| 경로 | 내용 |
| --- | --- |
| `app/` | 화면 경로와 서버 API(Route Handler) |
| `components/` | 화면 컴포넌트 |
| `lib/client/` | 브라우저에서 도는 로직(DuckDB-WASM, 파일과 기획서 읽기, 관계, 추론) |
| `lib/server/` | 서버 로직(MySQL, 접속 정보 암호화, 로컬 파일, 환경변수) |
| `scripts/` | 설치 후 워커 파일 복사, 테스트 데이터 생성 |
| `docs/DESIGN.md` | 설계 문서 |
| `start.bat` | Windows 실행 파일 |
