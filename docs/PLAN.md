# 회사 도구 기능 옮기기 작업 계획

* **작성**: 2026-11-06
* **바탕**: 「data-view 집 작업 목록」(2026-11-05). 그 문서의 절과 번호(1-3은 1절 3번)를 그대로 쓴다.
* **지금 상태 기준**: `feat/file-source` 브랜치의 20단계(테이블 열 정보 줄)까지
* 이 문서와 코드, 커밋 메시지, 테스트 데이터에는 회사 테이블 이름이나 실제 값을 쓰지 않는다(0-4). 예시는 모두 지어낸 것이다.

## 지킬 것 (0절 요약)

- 집에서는 가짜 테스트 데이터(`npm run fixtures`)로만 만들고 시험한다. 실제 데이터 확인은 회사에서 한다.
- 이 저장소는 집 작업용이다. 회사로 코드를 옮길 때는 정보보안실이 정한 방법만 쓰고, 이 저장소(개인 GitHub)를 거쳐 가져가지 않는다.

### 2절 가짜 데이터

지금 생성 스크립트에는 2-1~2-11의 모양이 하나도 없다(`#Design`, `#Definition` 시트, 머리글 줄 위치, `;` 비활성 행, 두 줄 머리글, `Level#1` 꼴 번호 열, `#` 메모 열, 문자열 키 `Str_`, 기획서 서식, 오타 쌍, 같은 한글 이름). 게임 데이터(퀘스트, 아이템 …)는 그대로 두고, 이 모양을 가진 파일을 따로 더한다(예: `fixtures/game2`).

| | 기능 | 지금 있는 것 | 남은 것 |
| :--- | :--- | :--- | :--- |

| 3-2 | 컬럼 표 | 열 정보 줄(20단계): 종류, 빈 칸, 값 종류, 가리키는 테이블 | 설명(`#Design`, 없으면 `#Definition` 표시), 값 예시 3개, `Level#1~n` 한 줄로 |
| 3-3 | 테이블 개요 | 시스템과 역할, 기획서 설명(TableDocNotes) | `#Design` 머리말, 가리키는 쪽 설명, 값 예시, 줄마다 출처 |

| 3-5 | 한글 이름 추론 | 기획서 이름 짝(아이템=Item)을 거꾸로 써서 한글 이름 | 단어 나누기, 단어 사전 csv, `A By B`/`A Per B`, 모르는 단어 덧붙이기, 「추론」 표시 |
| 3-6 | 같은 한글 이름 구분 | 없음 | 괄호 붙이는 규칙 |

| 3-9 | 행 출처 전환 | 엑셀과 DB가 다른 소스로 따로 보임 | 같은 테이블에서 엑셀 행 / DB 행 스위치, 비활성 행 줄긋기 |

## 3. 정할 것

- **용어(3-13)**: 12단계에서 QA용으로 바꾼 말(연결, 쓰는 테이블/쓰이는 곳, 시스템)과 회사 도구의 말(참조 관계, 참조 대상/참조하는 곳, 컬럼)이 다르다. 이 계획은 회사 도구의 말을 따른다. 「시스템」(도메인)은 회사 도구에 없는 말이라 그대로 둔다.
- **읽을 폴더(1-4)**: 묶을 폴더를 어디서 정할지. 이 계획은 `.env.local`의 `DATA_VIEW_ROOTS`(여러 개면 `;`로 나눔)로 정하고, 정하지 않으면 저장소 폴더의 `fixtures`만 허용하는 쪽으로 한다.
- **키 위치(1-3)**: 키를 Windows 사용자 폴더(`%APPDATA%\data-view\secret.key`)에 두고, 화면에서 입력해 저장하는 기능은 `.env.local`에서 켤 때만 보이게 한다.
- **설치본(5-10)**: Node를 함께 넣은 압축본을 만들지, 회사에서 허용하는 다른 방법이 있는지 정보보안실 기준을 먼저 본다.
